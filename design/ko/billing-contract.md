# 청구 조회 계약과 남은 검증

[English](../en/billing-contract.md) · [아키텍처](architecture.md) · 2026-09-19

읽기 전용 어댑터는 `GET /v1/bill/live`와 `GET /v1/bill`을 구현하며 T072 이후 `iwinv_current_bill`·`iwinv_bills`로 등록했습니다.
`iwinv_bill` 상세 조회 acceptance는 별도 차단 상태이며
목록을 상세의 group/item 대신 사용하거나 전체 청구 작업이 구현됐다고 표시하지 않습니다.

## 공식 문서와 실측 차이 (C32)

live 엔드포인트는 이달 시작부터 현재까지의 부가세 제외 예상 금액을 설명합니다. 청구 ID·시작/끝 날짜·정수 금액·통화의
배열을 반환하며 관측 ID는 문서의 `BILL-live` 상수였습니다. 영구 청구서 한 개로 단정하지 않고 모든 행을 보존합니다.
현재 예상 금액은 확정 청구나 삭제한 인프라의 과금 종료 증거가 아닙니다.

목록에는 정확한 청구 ID, 사용 기간, 청구일, 유형·상태·이름, 부가세 제외 금액, 부가세, 총 결제금액, 통화, 결제일이 있습니다.
공식 CLI는 KRW를 원으로 표시합니다. 실측한 정수 KRW에서는 금액+부가세가 총 결제금액과 일치했습니다.
어댑터는 배율·환산·부가세 계산·합계 일치 강제를 하지 않습니다. 할인·환불·크레딧·다른 통화는 검증하지 않았습니다.
부동소수점 반올림 없이 정확한 signed int64 금액을 보존합니다.

관측한 API 날짜는 문자열이고 공식 필터 입력은 YYYY-MM-DD입니다. 이 출처에는 청구 시간대와 월초 계산 경계가 명시돼 있지 않습니다.
반환 날짜 원문을 유지하고 UTC 변환·자정·시간대 offset을 추가하지 않습니다. 서명용 timestamp의 UTC 의미를 청구 날짜에 적용하지 않습니다.
합성 테스트는 빈 결제일을 보존하지만 실환경에는 결제일이 있었으므로 미납 변형은 추가 근거가 필요합니다.

문서는 `count`를 전체 건수, 페이지 메타데이터를 정수로 설명하지만 실측 목록은 **현재 페이지 행 수**와 문자열
`page_no`/`page_size`를 반환했습니다. 크기 1인 서로 다른 두 페이지가 크기 2인 한 페이지와 일치했습니다.
count는 행 수, 페이지·크기는 요청과 대조하며 페이지 메타데이터만 문서의 정수와 실측한 정규 정수 문자열을 수용합니다.
짧거나 빈 성공 페이지까지 순회하고 정확한 ID를 보존하며 중복과 최대 페이지 수를 검사합니다.
snapshot token이 없어서 조회 중 삽입·변경으로 생기는 일부 누락은 건수만으로 발견할 수 없습니다.

## 필터와 빈 결과

같은 시작/종료 날짜와 같은 최소/최대 금액은 경계를 포함했습니다. 사용 시작일과 청구일이 다른 행을 골라 조회했을 때
청구일로는 포함되고 사용 시작일로는 제외됐으므로 이 실측의 날짜 필터 기준은 **bill_date**입니다.
금액 필터는 총 결제금액이 아닌 부가세 제외 `price`를 비교합니다. 요청 전 날짜·범위 순서를 검증하고 응답이 모든 필터와 맞는지 검사합니다.
독립적인 단측 날짜·금액 범위와 음수 금액 필터도 전체 기준 목록과 일치했으며 실제 환불·크레딧 기록을 검증한 것은 아닙니다.

일치하는 청구가 없는 필터는 HTTP 400·정확한 `EMPTY_SET`, 끝을 지난 페이지는 HTTP 200·빈 배열·현재 페이지 count 0이었습니다.
이 목록 엔드포인트의 첫 페이지에서만 정확한 HTTP 400/`EMPTY_SET`을 빈 결과로 처리합니다.
중간 페이지 오류는 `EMPTY_SET`도 포함해 전체 조회를 실패시키며 부분 결과를 내보내지 않습니다.
일반 400/404·권한 오류·live/상세 오류를 빈 결과로 바꾸지 않고 자동 재시도도 하지 않습니다.

## 개인정보와 Terraform 설계

목록에는 결제 수단 정보·영수증·세금계산서 링크도 있습니다. 타입 모델·진단·공개 fixture·기본 Terraform 스키마에서
의도적으로 제외합니다. 이 링크를 따라가거나 내려받지 않습니다. 기존 기록은 읽기 전용이며 이 API 작업은 결제·환불·계정 변경·메시지 발송을 허용하지 않습니다.

등록한 스키마는 재무 출력을 sensitive로 표시하고 Terraform state에는 여전히 저장됨을 설명합니다.
raw JSON을 노출하는 지름길을 사용하지 않습니다. 전체 목록은 클라우드 리소스를 소유하지 않고 import가 필요 없으며 ID 순서를 안정적으로 정렬합니다.
현재 예상 금액은 refresh마다 정상적으로 달라질 수 있습니다. 이름과 날짜 원문을 보존하고 상세 추가 필드는 접근 복구 후 필드별 개인정보·식별자 결정을 내립니다.

## acceptance와 상세 조회 차단

T071: `TestAccBillingReads`는 Go race에서 18.07초로 통과했습니다. 현재 예상 금액, 여러 페이지 목록, 전체 기준 목록과 정확한
날짜·금액 조합·독립 단측·음수 범위 필터 결과 대조, 빈 필터 계약을 검증했습니다. 쓰기는 없었습니다.
합성 검사는 2^53보다 큰 정확한 금액, 결제정보·URL 제외, 이름 원문, 잘못된/null 필드, overflow·소수 금액,
건수/페이지 불일치, 중복 페이지, 순회 상한, 취소, 필터 검증과 부분 결과 없는 실패를 다룹니다.
이 단계는 타입 어댑터 근거이며 이후 Terraform acceptance는 아래에 기록합니다.

목록에서 얻은 서로 다른 ID 두 개와 문서의 `BILL-live` 상세 ID 모두 `GET /v1/bill/{bill_id}`에서 HTTP 403 `CHECK_IP`·
중첩 code 9를 반환했습니다. 같은 로컬 인증정보의 목록·예상 금액은 성공했습니다.
이 엔드포인트별 거절 원인은 미해결이며 키나 전역 IP 허용 목록이 잘못됐다는 증거는 아닙니다.
조건 변경 없이 재시도하거나 허용 IP를 변경하지 않고 상세 성공 fixture를 만들지 않습니다.
상세 인증 검증은 접근 조건 변경이나 공급사 설명이 필요하며 문의는 보내지 않았습니다.
시간대·상세 단위·중첩 민감 필드가 완전히 검증되지 않아 T042는 진행 중입니다. 별도 웹메일 정리 T056도 미해결입니다.

## Terraform acceptance (T072)

`TestAccBillingDataSources`는 Terraform 1.14.2·Go race에서 23.68초로 통과했습니다. 현재 예상 금액·전체 목록·빈 날짜 필터,
재무 state 민감 표시와 관측한 안정 구간의 무변경 plan을 검증했으며 쓰기는 없었습니다.
합성 Core는 2^53보다 큰 정확한 int64, plan의 민감 값(먼저 조회되어 prior state에 들어간 Data Source 포함),
출력 변경·state 민감 표시, 표시 없는 루트 출력 거절, unknown·0·음수 필터, 현재 결과 0개/여러 개, 중간 실패와
저장 산출물에서 결제수단·문서 링크 제외를 검증합니다. 재무 값 자체는 저장됩니다.
[현재 예상 청구](../../docs/ko/data-sources/current_bill.md)와 [청구 목록](../../docs/ko/data-sources/bills.md)을 참고하세요.
