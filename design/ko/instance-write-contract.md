# 인스턴스 쓰기 계약 준비

[English](../en/instance-write-contract.md) · [조회 경계](instance-read-contract.md) · [목차](../../README.md)

## 등록된 수명주기가 아닌 내부 후보

`InstanceWriter`는 읽기 전용 `Service.API`와 분리해 문서화된 생성·정보 수정·삭제 요청을 준비합니다. 등록된 Terraform 리소스에서 호출하지 않습니다. 2026-09-23에 호환 카탈로그의 다른 상품으로 API 생성을 다시 시도했지만 같은 존 이용 제한 오류가 발생했습니다. 일반 존의 콘솔 생성은 성공했으나 API 생성 성공이나 Terraform 수명주기 검증은 아닙니다. 공개 등록은 Data Source 18개·리소스 7개입니다.

2026-09-19 확인한 출처: [생성](https://iwinv.readme.io/reference/postv1instances), [정보 수정](https://iwinv.readme.io/reference/putv1instancesinstanceid), [삭제](https://iwinv.readme.io/reference/deletev1instancesinstanceid), [필드 마스크](https://api-kr.iwinv.kr/fields/v1/instances).

## 요청과 소유권 결정

| 작업 | 후보 요청 | 의미와 남은 조건 |
| --- | --- | --- |
| 생성 | Multipart POST, 정확한 존·이미지·상품 ID, count=1 고정 | 서버 하나에 Terraform 소유자 하나; 일괄 개수 입력 없음 |
| 선택 생성 입력 | 이름·설명, 정렬해 쉼표로 연결한 SSH 키 ID, 기존 스크립트 ID | nil은 생략; 중복·잘못된 ID는 전송 전 거절하고 입력 slice는 변경하지 않음 |
| 정보 수정 | fields=3599 쿼리와 multipart PUT; 지정한 이름·설명만 전송 | nil은 생략; 명시적 빈 설명은 보내지만 실제 초기화 동작은 미검증 |
| 삭제 | 정확한 ID에 본문 없는 DELETE 한 번 | 예상 202·deleting 상태는 접수이며 확정된 부재가 아님 |

문서의 URL 인코딩 요구에 따라 이름·설명에 `url.QueryEscape`를 한 번 적용한 뒤 multipart로 직렬화합니다. 이 후보는 공백을 `+`로 나타냅니다. 실제 서버의 디코딩, Unicode 길이 단위·허용 문자·정규화는 실환경 검증이 남아 있습니다. 지정한 이름은 비어 있지 않은 유효 UTF-8, 설명은 유효 UTF-8이어야 합니다. 미확정된 공급사 문자·길이 의미까지 검증한다고 주장하지 않으며 공통 클라이언트의 요청 크기 제한은 적용됩니다.

인라인 블록 스토리지, deprecated 보안 그룹·공인 IP 입력, resize·rebuild·전원, 준비 완료 대기와 import는 이 메서드 범위 밖입니다. 관련 소유권·API 계약은 프로젝트의 남은 작업으로 유지합니다. SSH 키 생략은 문서상 비밀번호 접근 모드지만 이 어댑터는 기본 비밀번호를 조회·저장하지 않습니다. 리소스 등록 전 사용 가능하고 안전한 접속 정책을 정해야 합니다.

## 복구용 접수 정보

성공 생성 응답은 중첩 Read 모델과 달리 평면 필드의 배열입니다. 예상 202·count=1·상태 구조를 검사하기 전에 유효한 응답 ID를 먼저 추출합니다. 식별 가능한 단일 행이면 나머지 접수 정보가 잘못돼도 `CreateReceipt.ID`를 반환합니다. 호출자는 오류를 처리하기 전에 이를 state 또는 작업 대장에 보존해야 합니다. 복수 행에서는 첫 ID를 고르지 않고 유효한 고유 ID 전체를 `RecoveryIDs`에 남겨 명시적으로 대조합니다. 실패 HTTP·API 오류 응답의 ID는 신뢰하지 않고 파싱할 수 없는 본문에서 ID를 추측하지 않습니다.

요청을 자동 재전송하지 않습니다. 전송 실패여도 원격에서는 처리됐을 수 있으므로 이름 기반 자동 채택이나 재시도를 하지 않습니다. 합성 접수 정보 보존은 Terraform Core의 state 보존 검증이 아닙니다. 이후 리소스에서 부분 실패·중단·복구를 별도 검증해야 합니다.

수정 응답은 요청 ID와 정확히 하나가 일치하고 고정된 안전한 조회 모델을 만족해야 합니다. 쓰기 후 잘못된 응답은 오류와 대조 대상으로 남기며 쓰기를 재실행하지 않습니다. 쿼리를 지원하는 multipart 클라이언트는 정규 경로를 검증하고 timestamp+path만 서명합니다. TLS 테스트 서버에서 쿼리 인코딩과 사전 인코딩된 multipart 값의 이중 인코딩 방지를 확인합니다.

삭제 접수 정보는 남는 블록 스토리지 ID를 정렬해 보존합니다. 문서상 서버 삭제가 해당 볼륨까지 삭제하지 않으므로 볼륨을 자동 삭제·채택하지 않습니다. 예상 밖 상태·count·구조 및 중복·잘못된 볼륨 ID는 명시적으로 실패합니다. 유효한 `DeletionReceipt`도 state 제거·실제 부재·과금 종료의 증거가 아닙니다. API 목록은 미지원 존을 제외하므로 빈 목록만으로 삭제 완료를 판단할 수 없습니다.

## 검증과 등록 조건

합성 테스트는 정확한 단일 생성 입력, 생략·빈 값 구분, Unicode 인코딩, 입력 불변성, count·status 오류에도 ID 보존, 예상 밖 복수·잘못된 행, 안전한 수정 조회, 남는 볼륨 접수 정보, 잘못된 경로·취소·전송/API 오류 비재전송을 검증합니다. fixture는 가상 값이며 공급사 예제의 비밀값이나 계정 응답은 커밋하지 않습니다.

T025는 비재전송 기반에 대해 진행 중으로 표시합니다. 실제 API 생성 제한을 기록한 T015는 failed를 유지하고 T029는 Terraform Core 수명주기 근거가 필요합니다. 등록 전 존 제약 해결, API 소유 fixture의 인코딩·생성 ID 확인, 제한된 준비 완료·확정 부재 대기, SSH·스크립트·스토리지 소유권, CRUD·import·plan, 실패 복구·정리 acceptance가 필요합니다. 성공한 실환경 API 인스턴스 생성·수정·삭제는 주장하지 않습니다.
