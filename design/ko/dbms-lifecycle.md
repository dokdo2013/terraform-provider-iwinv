# DBMS 수명주기 결정

[English](../en/dbms-lifecycle.md) · [아키텍처](architecture.md) · 2026-09-19

`iwinv_db_instance`는 공개 제어 API의 서비스와 전체 IPv4 허용 목록을 관리합니다.
T062는 타입 어댑터, T063은 Terraform Core와 STD Redis 실환경 수명주기 acceptance입니다.
다른 엔진, DB 접속, 백업/이전, 과금 종료와 전체 T038은 미검증입니다.
실제 스키마는 [리소스 가이드](../../docs/ko/resources/db_instance.md)를 참고하세요.

## 식별자·설정·import

`service_idx`는 2^53 초과 값까지 정확한 양의 int64 십진 문자열로 보존합니다.
Read는 전체 서비스 목록을 검증한 뒤 ID를 선택하며 잘못된/중복 행, 바뀐 페이지·건수 메타데이터를 거부합니다.
생성 응답은 상품 ID를 생략하고 도메인이 문자열인 반면 Read는 상품 ID와 라벨→도메인 객체를 제공합니다.
별도 타입 모델을 사용하며 읽기 모델에는 임의 자격증명이나 초기 계정 이력을 복사하지 않습니다.

Read는 상품, 원문 이름/설명, 허용 목록, 상태, 등급/버전과 도메인을 복원합니다.
기본 도메인을 `address`로 제공하되 포트나 로그인 계정을 추측하지 않습니다.
초기 계정명은 API가 반환하지 않으므로 `account_name`은 import 시 선택적인 과거 입력이며 생성 시 필수입니다.
추가·변경·제거는 교체 요청입니다. 이를 생략한 전체 읽기 속성 import 비교와 영속 재import 후 무변경 plan을 통과했습니다.
로컬 타임아웃은 import하지 않습니다.

공개 수정 API는 허용 목록뿐입니다. 나머지 생성 설정은 전체 서비스와 데이터를 교체합니다.
일반 교체는 확정된 다른 계정명을 요구하되 import 이력이 없으면 새 입력 이름의 과거 사용 여부를 확인할 수 없습니다.
변경될 생성 속성이 unknown이면 보수적으로 교체를 계획하며 unknown 계정명으로 교체하지 않습니다.
명시적 taint/`-replace`와 외부 삭제는 속성 비교를 우회할 수 있으므로 새 계정과 plan을 검토해야 합니다.
호스팅의 계정명 24시간 재사용 제한을 DBMS에 일반화하지 않으며 DBMS의 재사용 가능 시점은 미확인입니다.

## 허용 IP 집합의 단일 소유자

“추가” 엔드포인트는 목록 전체를 교체합니다. 따라서 부모 리소스의 `allowed_ips`를 비어 있지 않은 필수 Terraform set으로 둡니다.
한 소유자가 전체 목록을 관리해 개별 IP 리소스 간 충돌과 독립 허용 목록 리소스의 삭제 의미 불확실성을 피합니다.
순서 차이는 diff가 아니며 외부 집합 변경은 감지·복구합니다. 빈 PUT은 거부되고 기존 집합이 유지됐습니다.
관측된 빈 집합은 읽을 수 있지만 관리 설정에는 하나 이상의 지원되는 IPv4 호스트를 지정해야 합니다.
CIDR·IPv6·null은 검증 전까지 쓰기 전에 거부하며 가짜 차단용 IP를 만들지 않습니다.

PUT은 JSON으로 한 번 전송합니다. 응답이 정확한 요청 집합인지 확인한 뒤 같은 설정의 active Read를 기다립니다.
타임아웃만 바꾸면 쓰지 않습니다. 수정 오류, 바뀐 응답, 대기 만료 시 이전 state를 유지해 refresh로 불확실한 원격 결과를 확인합니다.
작업 중 오류 등을 부재로 취급하거나 쓰기를 자동 반복하지 않습니다.

## 상품 모호성 (C30)

새로 조회한 전체 카탈로그는 113행이었으며 `available`인데 `product_id`가 빈 문자열인 행이 4개였습니다.
어댑터는 ID를 만들거나 조용히 누락하지 않고 선택 불가능한 행으로 그대로 보존합니다. null/누락은 여전히 계약 오류입니다.
생성은 빈 ID를 거부합니다. 버전 간 중복 상품 ID도 보존하고 ID/등급/버전 조합이 완전히 중복된 경우만 거부합니다.
POST는 버전 선택값을 지원하지 않습니다. `engine_version`은 설정이 아닌 관측값이며 카탈로그 노출이 생성 자격을 보장하지 않습니다.
`spec.type`은 등급이지 엔진 이름이 아닙니다. 가격/VAT, vCPU, 메모리, 디스크 단위는 공개 타입 모델에서 제외합니다.
내부 카탈로그는 문서화된 엔진/등급 필터를 받으며 이번 실환경 검증은 전체 조회와 STD/redis 조합입니다.
조회 전용 [`iwinv_db_instance_products`](../../docs/ko/data-sources/db_instance_products.md)를 등록했습니다. T064는 공식 엔진 필터 6개, 등급 필터 2개, STD/redis 조합과 무변경 plan을 별도로 검증합니다. ID 집합으로 단순화하지 않고 전체 행을 보존합니다.

테스트 상품은 공식 `type=STD&db=redis` 쿼리로 선택했습니다. 상품명은 축약된 표기이며 응답에 엔진 식별자가 별도로 반환되지 않습니다. 이 근거의 “STD Redis”는 해당 필터로 선택한 범위이며, 엔진 종류나 실제 DB 접속을 독립 검증했다는 의미가 아닙니다.

## 복구와 검증 근거

생성은 나머지 응답 검증이나 준비 대기 전에 확실한 ID를 기록합니다. 잘못된 응답, 미검증 201/202 계약,
노출 지연과 대기 만료에도 식별자를 보존합니다. 아직 검증되지 않은 생성은 정상 목록에서 빠져도 Read가 잊지 않습니다.
정리 시 해당 ID에 한 번 삭제하고, 과거 active였던 서비스의 검증된 부재는 state에서 제거할 수 있습니다.
삭제는 응답과 정확한 ID 부재를 요구하며 독립적인 과금 확인과 구분합니다.
웹메일의 모순된 부재 계약은 T056에서 별도로 추적하며 재사용하지 않습니다.

T062는 STD Redis 두 개를 생성해 원문/생략 설명, 전체 목록 노출, 두 IP로 교체, 다른 서비스 보존과 삭제 응답/부재를 검증했습니다.
T063은 두 리소스를 함께 유지하며 총 4개 서비스 ID의 허용 목록 수정/drift 복구, 전체 import,
계정 이력 없는 영속 재import, 새 계정 우선 교체, 외부 삭제/재생성과 최종 정리를 검증했습니다.
6개 ID 모두 비공개 대장에 기록하고 삭제를 확인했으며 기존 리소스는 변경하지 않았습니다.

합성 테스트는 잘못된 생성 응답 후 Core 정리, unknown 입력, 생성 노출 지연, API/읽기/쓰기 오류,
대기 만료, 생성 계정 누락, 미지원 빈/IPv6/CIDR 집합, 교체 guard와 명시적 교체 plan도 검증합니다.
실제 패킷 동작, 클라이언트 접속, 백업·이전, 다른 엔진과 버전 선택을 검증했다고 주장하지 않습니다.
