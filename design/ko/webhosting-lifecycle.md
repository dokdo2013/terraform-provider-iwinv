# 웹호스팅 수명주기 결정

[English](../en/webhosting-lifecycle.md) · [아키텍처](architecture.md) · 2026-09-19

**개발 Provider에 `iwinv_webhosting`을 등록했고 SHARE PHP 8.4 범위의 T060을 통과했습니다.**
실제 스키마와 예제는 [리소스 가이드](../../docs/ko/resources/webhosting.md)를 참고하세요.
상품/서버 카탈로그 Data Source는 T061을 통과했습니다. 다른 상품/버전 수명주기 acceptance와 전체 T038은 미완료입니다.

## 교체와 계정명 재사용

공개 API는 조회·생성·삭제만 제공하므로 원격 생성 속성을 변경하면 전체 계정을 교체합니다.
공급사는 삭제한 계정명을 24시간 재사용할 수 없다고 명시합니다(C29). 이 기간과 24시간 이후 재생성을 실측한 것은 아닙니다.

일반 교체 plan은 삭제 전에 기존과 다른 확정된 계정명, 서버 선택, 초기 비밀번호 두 개를 요구합니다.
변경될 속성이 unknown이면 보수적으로 교체를 계획하며, 계정명이 unknown인 교체는 차단합니다.
타임아웃만 변경하면 로컬 상태만 갱신합니다. 합성 Core 테스트로 이러한 동작과 교체 입력 누락을 검증했습니다.

명시적 `-replace`, taint, 외부 삭제 후 재생성은 기존 속성과의 비교를 우회할 수 있습니다.
같은 계정명으로 실제 재생성하지 않고 plan-only 테스트로 Core의 교체 동작을 확인했습니다.
이 경우 사용자가 새 계정명을 선택해야 합니다. Provider는 24시간 생성 재시도나 비공개 수정/비밀번호 API를 사용하지 않습니다.

실환경 acceptance는 별도 서비스 하나를 유지하면서 새 계정을 먼저 생성한 뒤 이전 계정을 삭제했습니다.
두 계정의 동일 도메인 재사용이나 콘텐츠·DB·DNS 이전까지 검증한 것은 아닙니다. 예제는 `prevent_destroy`를 사용하며,
백업·이전·전환은 사용자가 별도로 수행해야 합니다. 삭제하면 호스팅 데이터가 제거됩니다.

## 소유 범위와 import

- 식별자는 양의 정수 `service_idx`를 정확한 십진 문자열로 보존합니다. float64 변환이나 이름 기반 자동 인수 없이 ID로 import합니다.
- Read는 상품, 계정명, 별칭, 설명, 방화벽 플래그, 상태, IP, 도메인 매핑을 복구합니다.
- `server_id`는 Read에 없는 생성 당시 선택값입니다. import에서는 생략 가능하고 생성/교체에서는 필수입니다.
  나중에 추가·변경·제거해도 교체되며, 저장값이 현재 서버 배치를 보증하지 않습니다.
- `custom_domains`는 전체 사용자 도메인→폴더 맵을 소유하고 `domains`는 전체 관측값입니다.
  문서화된 자동 도메인 `account_name.iwinv.net`이 응답에 있는지 확인한 뒤 설정 소유 범위에서 제외합니다. 없으면 오류입니다.
- 외부 사용자 도메인 변경은 drift입니다. 설정을 맞춰 인수하거나 새 계정으로 교체할 수 있습니다.
  DNS·폴더 생성은 관리하지 않습니다. 기본 `/` 매핑은 실측했으나 임의 폴더의 정규화는 미검증입니다.
- 생성 이력이 없는 import는 `server_id`, 비밀번호, 로컬 `password_wo_version`을 생략하고 읽을 수 있는 설정을 맞춥니다.
  전체 속성 비교 import와 실제 상태에 재import한 뒤 무변경 plan을 검증했습니다.

## 비밀번호 처리

초기 FTP/DB 비밀번호는 서로 다른 `Sensitive` + `WriteOnly` 입력이며 plan이 아닌 `req.Config`에서 읽습니다.
생성/교체 때만 필수이고 값이나 해시를 보존하지 않습니다. write-only 값만 바꾸면 plan이 생기지 않으므로,
선택적인 양수 `password_wo_version`으로 전체 계정 교체를 요청합니다. 제자리 비밀번호 교체 기능이 아닙니다.

합성·실환경 테스트는 ephemeral sensitive 변수를 사용하고 파싱한 plan, 실제 압축된 저장 plan 내용, state에 입력 비밀번호가
없는지 검사했습니다. import는 비밀번호를 요구하거나 가짜 기본값을 만들지 않고, 읽기 모델은 응답에 포함된 비밀번호를 제외합니다.
지원 입력은 서로 다른 7–20자의 출력 가능한 ASCII이며 문자/숫자/기호 중 두 종류 이상입니다.
공급사의 모든 비밀번호 경계를 실측한 것은 아닙니다. [HashiCorp 지침](https://developer.hashicorp.com/terraform/plugin/framework/resources/write-only-arguments)을 따릅니다.

## API와 실패 복구 경계

타입 어댑터는 전체 목록을 검증하고 중복/잘못된 행, 바뀐 페이지·건수 메타데이터를 거부하며 int64 식별자를 보존합니다.
이름과 설명은 원문 그대로입니다. 명시적 빈 설명은 HTTP 422였으므로 리소스의 기본 빈 설명은 생성 요청에서 생략합니다.
상품 모델에는 단위가 미확인된 가격·VAT·저장공간·트래픽을 포함하지 않습니다.

생성 요청은 한 번만 보내고, 응답의 확실한 ID를 나머지 필드 검증 전에 저장한 뒤 관리 속성이 일치하는 active Read를 기다립니다.
HTTP 201/202 응답에서 식별자를 확보하면 ID를 보존하면서 미검증 성공 계약 오류를 냅니다.
잘못된 응답, 지연된 목록 노출, 대기 만료 시 ID를 유지합니다. 아직 검증되지 않은 생성이 성공 목록에 없더라도 잊지 않습니다.
Read는 ID를 보존한 오류를 내고, destroy는 해당 ID에 삭제 요청을 한 번 보냅니다.

과거 active였던 서비스가 완전한 정상 목록에서 사라지면 외부 삭제로 처리합니다. API 오류/404는 부재가 아닙니다.
삭제는 응답 확인 뒤 정확한 ID의 부재를 검증하며 쓰기를 자동 반복하지 않습니다.
콘솔에 존재해도 정상 API 목록에서 빠지는 웹메일에 이 호스팅 계약을 일반화하면 안 됩니다.

## 검증 범위와 남은 항목

T059는 어댑터 계약입니다. T060은 실환경 Core 생성/조회/무변경 plan, 전체 import, 이력 없는 재import,
새 계정 교체, 다른 서비스 보존, 외부 삭제/재생성, 비밀번호 산출물 비저장과 4개 ID 정리를 포함합니다.
합성 테스트는 생성 실패 ID 정리, 숨겨진 생성 복구, unknown 입력, 오류/타임아웃, 외부 도메인 drift,
교체 입력 누락, 명시적 교체 plan도 검증합니다. CI는 합성 데이터만 사용합니다.

HTTP/FTP/DB 연결, 데이터 이전, 임의 상품/버전/도메인 조합과 과금 종료는 미검증입니다.
별도로 추적하는 웹메일 정리 문제 때문에 T056은 실패 상태를 유지합니다. 호스팅 정리가 이를 해결하지 않습니다.
서명 Registry 릴리스는 아직 없습니다.
