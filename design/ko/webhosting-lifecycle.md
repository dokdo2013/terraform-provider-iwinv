# 웹 호스팅 수명주기 설계

[English](../en/webhosting-lifecycle.md) · [아키텍처](architecture.md) · 2026-09-19

**설계 단계입니다. 호스팅 API 어댑터는 구현했지만 `iwinv_webhosting` 리소스와 상품 Data Source는 등록하지 않았습니다.**
아래 속성 이름은 제안이며 실행 가능한 HCL 계약이 아닙니다. 전체 서비스 완료 조건은 T038에 남아 있습니다.

## 교체가 단순하지 않은 이유

공개 호스팅 API에는 상품/서버/서비스 조회, 생성과 삭제만 있고 수정 경로가 없습니다.
공식 삭제 문서는 계정 삭제를 복구할 수 없으며 같은 계정명을 삭제 시점부터 24시간 동안 재사용할 수 없다고 설명합니다(C29).
이는 문서상 제약이며 실제 재사용 가능 시각이나 24시간 경과 후 재생성을 실측한 결과는 아닙니다.

이름·설명 수정까지 무조건 `RequiresReplace`로 처리하면 기존 서비스의 데이터가 삭제된 뒤 같은 계정명으로 재생성하지 못할 수 있습니다.
`create_before_destroy`도 같은 계정명으로 두 서비스를 만들 수 있다는 보장이 없습니다.
Provider는 변경이 없는 것처럼 설정을 무시하거나, 비공개 수정 API를 추측하거나, 24시간 동안 자동 재시도하지 않습니다.

리소스 등록 전 다음 정책을 Terraform Core 테스트로 확정합니다.

- 읽을 수 있는 생성 속성의 변경은 원격 수정을 가장하지 않고 명시적인 교체로 표현합니다.
- 자동 교체 계획은 사용자가 새 계정명을 지정했는지 검사합니다. 기존 계정명 유지와 plan 시점 unknown을 어떻게 안전하게 거부할지 검증합니다.
- `-replace`, taint, 외부 삭제 후 재생성에도 재사용 제한이 적용됩니다. Provider가 모든 Core 교체 사유를 사전에 감지할 수 있다고 약속하지 않습니다.
- 데이터 백업·이전과 DNS 전환은 별도 작업입니다. `prevent_destroy` 안내를 제공하고, 새 계정으로 먼저 구성한 뒤 전환하는 예제를 검증합니다.
- 명시적 계정 교체가 성공해도 기존 웹 콘텐츠/DB/사용자 도메인 소유권이 자동 이전되는 것으로 설명하지 않습니다.

## 속성·소유권 제안

| 제안 속성 | 원격 계약 / 소유권 | import와 변경 결정 |
| --- | --- | --- |
| `id` | 양의 정수 `service_idx`를 정확한 십진수 문자열로 보존 | 정확한 ID만 import; 이름으로 채택하지 않음 |
| `product_id` | 실제 상품 ID | Read 복원, 변경은 교체 후보 |
| `server_id` | 상품별 서버 카탈로그의 정수 `idx`를 문자열로 전송 | 생성에 필수, 서비스 Read에 없음. import에서 값을 만들지 않음 |
| `account_name` | API의 `id`; 서비스 ID와 다른 로그인 계정명 | Read 복원, 새 생성에는 영문 6–12자. 변경은 교체 |
| `name`, `description` | 별칭/설명, 원문 보존 | Read 복원, 공개 수정 API 없음. 빈 설명은 생성에서 생략 |
| `web_firewall_enabled` | `security`의 Y/N | 두 값의 제어면 왕복을 확인. 실제 차단 정책 효과는 별도 검증 |
| `domains` | 도메인→연결 폴더 object | 전체 Read 집합과 사용자 입력 집합을 분리 설계; 기본 도메인을 중복 소유하지 않음 |
| `ftp_password_wo`, `database_password_wo` | 서로 다른 생성 비밀번호 | WriteOnly + Sensitive, req.Config에서만 읽고 plan/state에 저장하지 않음 |
| `status`, `ip_address` | 제어면 상태와 IP | 읽기 전용. `active`는 HTTP/FTP/DB 접속 성공의 증거가 아님 |
| `timeouts` | 로컬 작업 기한 | 생성 지연·삭제 확인·취소를 제한하며 쓰기 재전송을 의미하지 않음 |

`server_id`는 생성 기록을 보존하는 입력이지 Read로 검증한 현재 설정이 아닙니다.
import에서는 생략할 수 있으면서 신규 생성에는 필수인 선택지를 검증합니다. import 후 값을 추가하는 행위를
기존 원격 설정의 확인으로 취급하지 않고, 설정 변경/교체 정책과 함께 명시해야 합니다.

비밀번호 변경은 write-only 값만으로 plan 차이를 만들지 못합니다. 버전 속성으로 교체를 명시할지,
초기 비밀번호로만 제한할지 결정하고 테스트해야 합니다. 공개 비밀번호 변경 API가 없으므로 제자리 회전을 약속하지 않습니다.
import 시 비밀번호를 요구하거나 기본값을 만들어 저장하지 않습니다.
[HashiCorp write-only 지침](https://developer.hashicorp.com/terraform/plugin/framework/resources/write-only-arguments)을 따릅니다.

## 내부 어댑터 경계

`internal/services/hosted/webhosting*.go`는 상품/서버 조회, JSON 생성, 전체 목록의 정확한 ID 선택과 삭제 접수만 제공합니다.
상품 카탈로그에서는 PHP 선택지와 도메인 정책을 읽지만 가격·부가세·디스크/트래픽 단위는 검증 전이므로 모델에서 제외합니다.
카탈로그 조회가 특정 조합의 실제 생성 가능성을 보장하지는 않습니다.

- 정수 ID를 float64로 변환하지 않습니다. 잘못된 ID는 요청 전에 거부합니다.
- 생성 ID는 나머지 필드·응답 메타데이터 검증 실패 전에 반환합니다. 호출자는 오류 처리 전에 ID를 보존해야 합니다.
- HTTP 201/202에서 명확한 ID를 받으면 복구용으로 반환하되 검증하지 않은 성공 계약은 오류로 보고합니다.
- 목록에 중복/잘못된 행이나 새 pagination 메타데이터가 있으면 전체를 실패 처리합니다. 앞부분만으로 부재를 판단하지 않습니다.
- 이름·설명·도메인을 HTML 디코딩하지 않습니다. 비밀번호와 알 수 없는 응답 필드는 읽기 모델로 복사하지 않습니다.
- 명시적 빈 설명은 실측 HTTP 422 계약 때문에 요청 전에 거부합니다. nil은 설명을 생략합니다.
- 비밀번호는 내부 입력에서 printable ASCII 7–20자, 문자 종류 2개 이상, 서로 다른 값으로 제한합니다. 모든 공급사 비밀번호 규칙을 완전히 실측했다는 의미는 아닙니다.
- 빈 도메인 map은 의미가 확인되지 않아 거부하며 nil은 기본 도메인을 요청합니다.
- 삭제 접수 성공과 후속 목록 부재를 구분합니다. API 오류/404를 부재로 바꾸지 않고 자동 쓰기 재시도를 하지 않습니다.

## 리소스 등록 전 검증 목록

- [ ] 신규 생성 및 ID를 받은 뒤 실패한 apply에서 Core state에 ID가 남고 destroy로 복구된다.
- [ ] plan 파일, state, private state, 진단에 두 비밀번호가 없으며 ephemeral 변수로 입력할 수 있다.
- [ ] 서버 선택·비밀번호 없이 기존 서비스 import 후 Read 및 무변경 plan이 가능하다.
- [ ] 일반 변경, unknown 입력, taint와 명시적 교체의 계정 재사용 위험을 가시화한다.
- [ ] 도메인 입력에 없는 기본 도메인의 Read, 외부 추가·제거, 폴더 정규화로 무한 plan이 생기지 않는다.
- [ ] 생성 직후 일시 부재/비동기 상태, 오류 상태와 취소 후 ID 보존을 검증한다.
- [ ] 두 서비스 병렬 수명주기, 외부 변경/삭제, 부분 실패 후 재실행, 정확한 ID 정리를 검증한다.
- [ ] 서비스별 삭제 확인과 청구 종료를 구분하고 데이터 손실을 사용자 가이드에 명시한다.
- [ ] 한국어·영어 리소스 가이드와 실제 바이너리 예제 검증을 함께 완료한다.
